1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
The Sahyadri Food Court Management System (FoodCourtMS) is a modern, transactional, 
and inventory-automated desktop database application built using:
- Frontend/GUI: Java Swing (with UIManager Nimbus Look and Feel)
- Connectivity: Java Database Connectivity (JDBC) API
- Database Backend: MySQL 8.x
- Security & Constraints: Multi-level validation, regex checks, transactional safety, 
  and foreign key integrity constraints.

Core Features:
- Student login with automatic registration verification.
- New Student registration with strict alphanumeric college seat number (USN) validation.
- Cashless wallet system (digital ledger) stored on the database to prevent manual errors.
- Dynamic menu browsing, category-based filtering, and live stock tracking.
- Interactive Shopping Cart with real-time stock-out validations.
- Robust transaction processing: Java JDBC Transaction block (disabling auto-commit, 
  locking database rows, checking stock availability, deducting wallet balance, 
  inserting order headers, batch-inserting line items, committing changes, and rolling 
  back the entire transaction on any failure to guarantee ACID compliance).
- Automated Inventory Management: A MySQL AFTER INSERT trigger on order items automatically 
  deducts stock quantities upon order completion.
- Admin Reporting Dashboard: Calls a MySQL stored procedure to calculate daily total orders, 
  revenue, and best-selling items, shows individual order log records, tracks counter-wise 
  revenue, and displays detailed student trends (average order value, favorite items, 
  and predicted department based on college USN format).

3. DATABASE SCHEMA DESIGN (MySQL)
--------------------------------------------------------------------------------
The database name is `food_court_db`. It consists of 5 normalized relational tables:

1. Student Table:
   - student_id: VARCHAR(50) - PRIMARY KEY (Enforces alphanumeric USN format, e.g., 4SF24CI005)
   - name: VARCHAR(100) - NOT NULL
   - email: VARCHAR(100) - UNIQUE
   - phone: VARCHAR(15) - NOT NULL
   - wallet_balance: DECIMAL(8,2) - DEFAULT 0.00

2. Counter Table:
   - counter_id: INT - PRIMARY KEY AUTO_INCREMENT
   - counter_name: VARCHAR(100) - NOT NULL
   - location: VARCHAR(100)
   - operator_name: VARCHAR(100)

3. Menu_Item Table:
   - item_id: INT - PRIMARY KEY AUTO_INCREMENT
   - counter_id: INT - FOREIGN KEY referencing Counter(counter_id) ON DELETE CASCADE
   - item_name: VARCHAR(100) - NOT NULL
   - price: DECIMAL(6,2) - NOT NULL
   - category: VARCHAR(50)
   - stock_qty: INT - DEFAULT 0

4. Orders Table:
   - order_id: INT - PRIMARY KEY AUTO_INCREMENT
   - student_id: VARCHAR(50) - FOREIGN KEY referencing Student(student_id) ON DELETE CASCADE
   - order_date: DATETIME - DEFAULT CURRENT_TIMESTAMP
   - total_amount: DECIMAL(8,2) - NOT NULL
   - status: VARCHAR(20) - DEFAULT 'Pending'

5. Order_Item Table:
   - order_item_id: INT - PRIMARY KEY AUTO_INCREMENT
   - order_id: INT - FOREIGN KEY referencing Orders(order_id) ON DELETE CASCADE
   - item_id: INT - FOREIGN KEY referencing Menu_Item(item_id) ON DELETE CASCADE
   - quantity: INT - NOT NULL
   - unit_price: DECIMAL(6,2) - NOT NULL

--- MySQL Trigger: after_order_item_insert ---
Fires: AFTER INSERT ON Order_Item for each row.
Reasoning: Offloads stock deduction logic from the application server to the database. 
It guarantees that whenever an item is ordered, the inventory counts are updated 
atomically, keeping the Front-of-House (Menu) and Back-of-House (Stalls) in sync.
Code:
```sql
DELIMITER //
CREATE TRIGGER after_order_item_insert
AFTER INSERT ON Order_Item
FOR EACH ROW
BEGIN
    UPDATE Menu_Item
    SET stock_qty = stock_qty - NEW.quantity
    WHERE item_id = NEW.item_id;
END //
DELIMITER ;
```

--- MySQL Stored Procedure: GenerateDailySalesReport ---
Signature: GenerateDailySalesReport(IN report_date DATE)
Returns: TotalOrders (INT), TotalRevenue (DECIMAL), BestSellingItem (VARCHAR)
Reasoning: Compiles sales statistics on the database engine. It calculates total transaction 
counts, sum of order receipts, and determines the best-selling item by summing quantity 
grouped by item_id and ordering desc limit 1.
Code:
```sql
DELIMITER //
CREATE PROCEDURE GenerateDailySalesReport(IN report_date DATE)
BEGIN
    DECLARE total_orders INT DEFAULT 0;
    DECLARE total_revenue DECIMAL(8,2) DEFAULT 0.00;
    DECLARE best_selling_item VARCHAR(100) DEFAULT 'None';
    
    -- 1. Get total orders
    SELECT COUNT(*) INTO total_orders
    FROM Orders
    WHERE DATE(order_date) = report_date;
    
    -- 2. Get total revenue
    SELECT IFNULL(SUM(total_amount), 0.00) INTO total_revenue
    FROM Orders
    WHERE DATE(order_date) = report_date;
    
    -- 3. Get best selling item of the day
    SELECT MI.item_name INTO best_selling_item
    FROM Order_Item OI
    JOIN Orders O ON OI.order_id = O.order_id
    JOIN Menu_Item MI ON OI.item_id = MI.item_id
    WHERE DATE(O.order_date) = report_date
    GROUP BY OI.item_id, MI.item_name
    ORDER BY SUM(OI.quantity) DESC
    LIMIT 1;

    IF best_selling_item IS NULL THEN
        SET best_selling_item = 'None';
    END IF;

    SELECT total_orders AS TotalOrders, total_revenue AS TotalRevenue, best_selling_item AS BestSellingItem;
END //
DELIMITER ;
```

5. JAVA SOURCE CODE WALKTHROUGH & LOGIC FLOW
--------------------------------------------------------------------------------

1. DBConnection.java:
   Centralizes JDBC connection logic. Loads the driver `com.mysql.cj.jdbc.Driver` dynamically. 
   Uses URL: `jdbc:mysql://localhost:3306/food_court_db` and references credentials.

2. Main.java:
   Sets Nimbus L&F for aesthetic Swing components and launches `LoginFrame` safely on the 
   Event Dispatch Thread.

3. LoginFrame.java:
   - Prompts for Student ID and Phone Number. Query: `SELECT name, wallet_balance FROM Student WHERE student_id = ? AND phone = ?`.
   - Registration Modal: Takes College USN, Name, Email, Phone, and Initial balance.
   - Strict USN Validation Check (Regex): `^4SF\d{2}(CI|CS|EC|ME)\d{3}$`. 
     Must start with college code (4SF), followed by 2 digits of admission year, 
     department (CI=AIML, CS=CSE, EC=ECE, ME=Mech), and a 3-digit sequence number.
   - Admin Login Gateway: Bypasses standard tables using a secure passphrase `admin123`.

4. MenuFrame.java:
   - Loads menu items dynamically based on categories selected in JComboBox.
   - Houses a shopping cart. When clicking "Add to Cart", the code validates that the requested 
     quantity does not exceed available stock.
   - Order history panel calculates dynamic queue estimates:
     `SELECT COUNT(*) FROM Orders WHERE (status='Pending' OR status='Preparing') AND order_id <= ?`.
     Calculates waiting time as `countAhead * 5` minutes.

5. OrderFrame.java (Critical Transaction Handler):
   - Implements strict ACID transaction control to prevent partial updates or negative balances:
     1. Disables auto-commit: `conn.setAutoCommit(false);`
     2. Validates wallet balance against Grand Total.
     3. Validates live database stock counts to prevent race conditions.
     4. Updates student wallet balance: `UPDATE Student SET wallet_balance = wallet_balance - ? WHERE student_id = ?`.
     5. Inserts order record into `Orders` table, fetching generated order ID.
     6. Batch inserts order detail rows into `Order_Item` table using statement batching:
        `psOrderItem.addBatch(); psOrderItem.executeBatch();`
     7. Commits the transaction: `conn.commit();`
     8. Rolls back the transaction: `conn.rollback();` in the catch block on any SQL exception.

6. AdminFrame.java:
   - Daily Revenue Tab: Calls stored procedure `CALL GenerateDailySalesReport(?)` using `CallableStatement`. 
     Displays results in JTable. Displays order logs for the day and a counter-wise sales breakdown join.
   - Student Insights Tab: Calculates branch based on USN characters (e.g. CI -> AIML). 
     Calculates total orders, total spent, and average order value. Shows favorite food item:
     `SELECT MI.item_name FROM Order_Item OI JOIN Orders O ... GROUP BY item_id ORDER BY SUM(quantity) DESC LIMIT 1`.
     Lists all historical orders with comma-separated item summaries using `GROUP_CONCAT`.
